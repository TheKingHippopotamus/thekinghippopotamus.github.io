Research artifact · raw record

HOW THIS VPS RUNS — SYSTEM MAP, RAW RECORD
Measured 2026-08-23, read-only, on the host being described.
Placeholder roots are used throughout: $FIN is the data-platform root, <office>
the security office, <sensor> the host sensor, <roster> the agent charter roster.
No absolute path, address or hostname appears below.

Every figure on the page is one of the rows here. Where a figure was reconciled
across chapters, the wording below is the only wording permitted for it.

================================================================================
1. THE HOST — one virtual server, not a fleet
--------------------------------------------------------------------------------
COMMAND
  free -g
  df -h /

OUTPUT
  Mem: total 11 GB · used 2 · free 6 · buff/cache 3 · available 9
  Swap: 0
  root filesystem 193 G total · 167 G used · 26 G available · 87% used

RESULT  verified — roughly 11 GB of memory and a 193 GB root filesystem, 87%
        used. Everything else in this record runs inside that envelope.

================================================================================
2. THE ESTATE ON DISK — databases vs. tree
--------------------------------------------------------------------------------
COMMAND
  find $FIN/Data -name '*.db' -type f -printf '%s\n' | awk '{s+=$1}END{print s}'
  du -sb $FIN

OUTPUT
  105,441,099,776 B across 54 files
  114,355,413,279 B for the whole tree

RESULT  verified — 105.4 GB (98.2 GiB) of database files across 54 files;
        114.4 GB (106.5 GiB) for the whole platform tree, which includes raw
        blobs, code, logs and backups. The two are never interchangeable, and
        the tree figure is never attributed to the databases.

================================================================================
3. ROWS UNDER GOVERNANCE
--------------------------------------------------------------------------------
COMMAND
  one read-only row count per governed surface, summed over 28 surfaces

OUTPUT
  397,679,393 rows across 28 named surfaces

RESULT  verified — the largest summands are dimensioned XBRL fact rows
        (103,444,701), XBRL company facts (125,307,255), institutional-holdings
        positions (72,027,463), filer-to-filing links (27,155,455), daily price
        bars (18,914,666) and the filing spine (18,697,338). The sum mixes
        grains — filings, facts, positions, speaker turns — so it is a count of
        governed rows, not of records or data points.

================================================================================
4. THE SCHEDULED SURFACE
--------------------------------------------------------------------------------
COMMAND
  systemctl --user list-timers --all --no-legend | wc -l
  crontab -l | grep -vcE '^\s*(#|$)'

OUTPUT
  43 timer units loaded and scheduled
  11 active cron lines

RESULT  verified — 54 scheduled jobs. This counts jobs, not runs per day. Two
        adjacent numbers are deliberately not published here: 50 timer unit
        files were authored by hand, and the user manager can see 52 units
        because the operating system supplies two of its own.

================================================================================
5. THE DECISION LOG
--------------------------------------------------------------------------------
COMMAND
  grep -cE '^## 20' <office>/ciso/DECISION-LOG.md
  wc -l <office>/ciso/DECISION-LOG.md
  first and last date token in the same file

OUTPUT
  4 dated sections · 510 lines · 2026-03-30 -> 2026-08-23

RESULT  verified — 4 rulings. Two of the four carry an explicit
        APPROVE-WITH-CONDITIONS verdict; the other two are an investigation plan
        and an execution record. The file also holds 12 dated sub-item bullets;
        those are entries, not rulings, and are not published as such.

================================================================================
6. THE HOST SENSOR
--------------------------------------------------------------------------------
COMMAND
  wc -l <sensor>
  layer table in the sensor source

OUTPUT
  1,611 lines · standard library only · 10 layers

RESULT  verified — one file, no third-party dependency, ten layers: kernel,
        network, auth, process, containers, storage, service, application,
        security, integrity. On an ordinary day it runs 288 three-layer passes,
        96 ten-layer passes, 24 janitor runs, 24 outbound-only linter runs and
        one daily digest. Those four counts measure different things and are
        never summed into one number.

================================================================================
7. THE AGENT ORGANISATION
--------------------------------------------------------------------------------
COMMAND
  ls -1 <roster>/*.md | wc -l
  grep -h '^name:' <roster>/*.md
  ls -1 <roster>/_archive/

OUTPUT
  8 charter files · 7 distinct seats · 1 role retired (2026-07-02)

RESULT  verified — one role carries two profiles, a full role definition and a
        lighter orchestrator definition, which is why 8 files cover 7 seats.

================================================================================
8. THE TRANSCRIPT CORPUS
--------------------------------------------------------------------------------
COMMAND
  SELECT COUNT(*), COUNT(DISTINCT ticker), MIN(call_date), MAX(call_date)
    FROM calls;                                  -- opened mode=ro

OUTPUT
  12,171 calls · 3,652 tickers · 2021-03-10 -> 2026-08-21

RESULT  verified — 12,171 is the corpus after deduplication. The two upstream
        stores hold 12,712 raw captures between them; the 541-row difference
        (4.3%) is removed by two passes, one that drops an archive capture when
        a live capture covers the same quarter, and one that keeps the fullest
        capture when a provider re-posts the same call under a new URL. The
        rows are deduplicated, not lost.

================================================================================
9. THE DATA OFFICE — CLAIM WITHDRAWN
--------------------------------------------------------------------------------
CLAIM TESTED
  "The four-seat data office is currently operating."

COMMAND
  ls <roster>/*.md
  stat the shared state directory those four charters declare as mandatory

OUTPUT
  four current, detailed seat charters present
  shared state directory: No such file or directory

RESULT  failed — the charters are current and the separation of powers in them
        is real as a design: the architect is the single write thread, the
        quality officer holds a unilateral block on publish and may not
        implement its own fixes. But the state store the seats close their tasks
        against does not exist on this host, so the office is designed
        governance, not a running system. It is described in the present tense
        only as a design.

================================================================================
10. THE PUBLISHED PACKAGES — CLAIM WITHDRAWN
--------------------------------------------------------------------------------
CLAIM TESTED
  "The three published Python packages install and run from a clean environment
   at their published versions."

COMMAND
  local CI, latest run per repository, plus the published version of each
  project read back from the index and compared with the working tree

OUTPUT
  CAD server   FAIL   index 0.2.1 · local fix branch 0.2.2 (unpublished)
  vault        PASS   index 3.1.1 · local fix branch 3.2.1 (unpublished)
  XBRL server  FAIL   index 2.1.0 · local fix branch 2.1.1 (unpublished)
  overall ATTENTION · tests in the working trees: 229 · 144 · 16
  end-to-end audit 12 pass / 4 fail

RESULT  failed — both failures are fresh-install failures against the published
        release, not against the code. The fixes exist, are tested and are not
        shipped, which is exactly the gap the row is here to record. The worst
        of the underlying defects was an unbounded dependency range that
        resolved to a major release which had removed the module the server
        imports at startup: the install exits 0 and the product cannot start.

================================================================================
11. PORTFOLIO CURATION — ARITHMETIC THAT DOES NOT CLOSE
--------------------------------------------------------------------------------
CLAIM TESTED
  "Every repository removed from public view is accounted for in the curation
   log."

COMMAND
  the day-0 census file: owned originals + forks
  grep -c 'private=true' / 'archived=true' / 'description set' on the curation log
  live count from the public listing endpoint

OUTPUT
  62 catalogued (48 owned originals + 14 forks, all public)
  9 made private · 21 archived · 9 descriptions rewritten — all HTTP 200
  50 public today, of which 21 archived and 14 forks · 17 stars in total

RESULT  failed — 62 catalogued minus 9 made private is 53, and 50 are listed.
        Three repositories in the census are no longer publicly listed and
        appear in no curation-log row, so their disposition is not evidenced.
        Archiving does not remove a repository from public view, so the 21
        archived do not close the gap either.

================================================================================
12. EXTERNAL VALIDATION
--------------------------------------------------------------------------------
CLAIM TESTED
  "Nothing here has been audited, reviewed or certified by a third party."

COMMAND
  none available — there is no external engagement to cite

RESULT  not testable — stated as a position rather than demonstrated. Every
        other row on this page is self-measured on the host it describes. The
        substitute for an external auditor is that each figure carries the
        command that produced it, that three of the twelve rows above came back
        failed and were kept, and that the publish pipeline's own verification
        stage re-derives the numbers from a fresh context rather than reading
        how they were derived — a stage which returned FAIL, with six numeric
        mismatches, on the first case study it was pointed at.
