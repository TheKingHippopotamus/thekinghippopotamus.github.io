RESEARCH & DISCOVERY METHOD — RAW RECORD
Re-run read-only 2026-08-23. Nothing below is taken from a README on trust:
every row is a command that was executed and the figure it returned.

The programmes described here live in a private operating environment, so the
roots are written as placeholders and no filesystem path appears in this file.

  $MATRIX    the forensic programme's objective-matrix document
  $PROTOCOL  its execution protocol (unit manifest, tracks, budgets, timeline)
  $PIPELINE  its pipeline document (automation ladder)
  $GATES     the gate + consolidation code directory
  $REGISTRY  the equity workbench's methodology registry
  $CAMPAIGN  the withdrawn campaign's preserved failure record
  $ROOTS     the two research roots scanned for plan-class documents

================================================================================
1. The objective matrix carries 66 rows across 33 themes — and the same
   document set contradicts itself about how many objectives there are
--------------------------------------------------------------------------------
COMMAND
  grep -cE '^\| \*{0,2}[0-9]+\.[0-9]+' $MATRIX
  grep -n  'Phase Map'                 $MATRIX

OUTPUT
  66            objective rows, spread across 33 themes
  header line   "Phase Map" declares 34 objectives
  the programme overview elsewhere states 31

RESULT  verified — 66 is the counted figure and the one published. The 31/34/66
        spread is published as-is: it is an honest finding about a specification
        that moved faster than its own summaries.

================================================================================
2. The execution protocol specifies 48 units on three tracks
--------------------------------------------------------------------------------
COMMAND
  sed -n '/Complete Agent Manifest/,/TOTAL/p' $PROTOCOL
  grep -c '^### ' $PROTOCOL
  wc -l           $PROTOCOL

OUTPUT
  48 units = 18 extraction + 13 analysis + 14 investigation + 3 assembly
  each row carries: track, tool-call budget, lock requirement, sequencing rule,
  fixed output path
  orchestration runs T=0 -> T=28 minutes across three tracks
  33 third-level sections (role cards and rules)
  1,764 lines

RESULT  verified

================================================================================
3. Five executable gates, four editorial gates, 3,593 lines of gate code
--------------------------------------------------------------------------------
COMMAND
  ls $GATES/gate*.py | wc -l
  grep -c '^### Gate ' $MATRIX
  wc -l $GATES/*.py

OUTPUT
  5     executable gate programmes, at the seams of the run:
        after extraction (file existence AND minimum sizes)
        after consolidation (balance-sheet identity, income-statement coherence,
          EPS consistency, segment reconciliation, period continuity,
          concept provenance, year-on-year sanity)
        after analysis · after investigation · before publication
        (size floors, zero unfilled template tokens, 15 canonical sections,
         three verdicts, banned interface elements)
  4     editorial gates in the research charter
  3,593 lines across 8 modules, of which 487 are universal arithmetic checks

  exit codes: 0 pass · 1 fail-blocking · 2 warn-and-acknowledge
  analysis units are required to read the second gate's result file and answer
  its warnings in their own reasoning — a warning is an obligation, not a pass.

RESULT  verified

================================================================================
4. The governing document set: 8,078 lines over 8 documents
--------------------------------------------------------------------------------
COMMAND
  wc -l   <the eight governing documents>
  wc -l   <the four core documents>

OUTPUT
  8,078   eight-document corpus
  3,562   four core documents

RESULT  verified — and it refutes the programme overview's own headline
        line-count for the analysis protocol, which reproduces against nothing
        in the current tree. The counted number is published; the claimed one
        is not.

================================================================================
5. The pinch point: 780 KB of raw facts become a 30-50 KB indexed document
--------------------------------------------------------------------------------
COMMAND
  grep -n 'Consolidated Facts Layer' -A 8 $PROTOCOL
  wc -l <the consolidation module>

OUTPUT
  raw filing extract measured at ~780 KB per company
  consolidated output 30-50 KB: income statement, balance sheet, cash flow,
    shares, segments, derived ratios
  all 13 analysis units declared disk-only — they read that one file and are
    forbidden the extraction tooling entirely, which also frees them from the
    single processing lock that serialises track A
  1,011 lines in the consolidation module

RESULT  verified

================================================================================
6. The withdrawn campaign: 8 reports, 7 tickers, 66 declared limitations
--------------------------------------------------------------------------------
COMMAND
  python3 -c "import json;m=json.load(open('$CAMPAIGN/METHODOLOGY-ALL-2026-08-05.json'));
              print(m['total_limitation_items'], len(m['tickers_included']))"

OUTPUT
  66 limitation items
  7  tickers  (8 reports = 7 plus one baseline)

RESULT  verified

================================================================================
7. The falsification pass: 19 findings — 3 H1 / 5 H2 / 11 H3
--------------------------------------------------------------------------------
COMMAND
  JSON tally over $CAMPAIGN/GAP-CLASSIFICATION-2026-08-05.json,
  compound verdicts assigned to their governing family

OUTPUT
  H1  genuine non-disclosure                          3
  H2  present at source, absent from the platform     5
  H3  present in the platform, never retrieved       11
      total                                          19

  The plan that generated this taxonomy states one question — "was the
  information genuinely unavailable, unavailable to us, or available and
  missed?" — and names H3 as the dangerous class: there a stated limitation is
  a misdescription. The report says "cannot be known" when it means "we did not
  look", and a conclusion drawn from a partial record can be wrong rather than
  merely incomplete. Even H1 is not taken on faith.

  Outcome: 8 of 8 reports destroyed, the public site rebuilt to zero posts, the
  domain closed pending a rebuilt process. Nothing was corrected or republished.
  The failure record was preserved deliberately.

RESULT  verified

================================================================================
8. One INNER JOIN sealed 55.8% of the corpus text
--------------------------------------------------------------------------------
SOURCE
  the study's own build record, written at the time of the fix

OUTPUT
  274,961,510 characters — 55.8% of the corpus text — were unreadable to every
  stage of the programme, because the mention layer joined against the
  question-and-answer table with an INNER JOIN. That is precisely the half in
  which a company states its own capacity, customers and constraints before any
  analyst speaks. 47% of the study's final cited material came from that half.

RESULT  not testable — read back from the record, not re-derived in this pass.
        The figure is load-bearing and is published with that caveat attached
        rather than dressed up as a fresh measurement.

================================================================================
9. The workbench generates its judgment worklist: 16 x 40
--------------------------------------------------------------------------------
COMMAND
  python3 -c "import json;d=json.load(open('$REGISTRY'));
              print(len(d['lines']), len(d['methodologies']))"

OUTPUT
  16 40

  16 lines of inquiry crossed with 40 recognised methodologies; every cell
  tagged DATA, COMPUTE or JUDGE, so the judgment worklist is generated rather
  than improvised. Deterministic computation at the centre, judgment at the edge.

RESULT  verified

       -o -iname '*PROTOCOL*.md' -o -iname 'PIPELINE*.md' \
       -o -iname '*INVESTIGATION-PLAN*' -o -iname 'METHODOLOGY*' \) | wc -l

OUTPUT
  10

RESULT  verified

OUTPUT
