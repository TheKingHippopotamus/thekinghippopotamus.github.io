What it is

IronDome is a terminal vault. Entries are encrypted locally with AES-128-CBC via Fernet, keyed by PBKDF2-HMAC-SHA256 at 600,000 iterations. There is no account, no sync and no telemetry — and a test suite walks every module and fails the build if one of them imports a networking library.

How it works

Every capability sits at one of four distances from a secret. Reading them from the outside in is also the order an attacker meets them.

At the perimeter

What can leave

The strongest claim on this page, because it is the one that is mechanically enforced.

Network

No network calls anywhere in the package

Not a promise not to sync — there is no code path that could. No sockets are opened and no ports are bound by anything you install.

$ grep -rnE "(socket|http|urllib|requests|ssl)" \
      password_manager/
(no matches)
CI

Enforced by a test, not by a sentence

A suite walks the AST of every module and fails the build on a networking import, a resolver call, or an http:// literal. The allowlist is empty, and a separate test asserts it stays empty — so restoring network access means editing this claim in the same commit.

ALLOWLIST: frozenset = frozenset()

assert ALLOWLIST == frozenset()
Erase

Self-destruct that reports its own failure

nuke clears the keyring entries, overwrites each file once with random bytes, fsyncs, and unlinks. Then it re-walks the directory: if anything survived, it returns success: False and names every leftover.

fh.write(os.urandom(size))
fh.flush()
os.fsync(fh.fileno())

  [OK] 7 file(s) securely deleted.

At the door

Getting in

Three ways to authenticate, and one way to be locked out.

Modes

Three security modes

Biometric only, biometric plus password, or password only. The mode is recorded in the OS keyring and drives the login flow.

1. Touch ID Only
2. Touch ID + Master Password
3. Master Password Only
Gate

Biometric is an OS gate, not key material

Touch ID, Windows Hello or fprintd runs in front of a vault key that lives in the OS keyring. Your fingerprint authorises the unlock; a process already running as you can read that key without presenting one. Use mode 2 if that matters to you.

# biometric.py — the check is a boolean, not a KDF input
return result.returncode == 0
Lockout

Adaptive lockout, per device

Three wrong passwords and the device is locked out for fifteen minutes. The counter is stored per machine and survives the process exiting.

MAX_LOGIN_ATTEMPTS = 3
LOCKOUT_DURATION   = 15 * 60

In session

While the vault is open

The window where a secret is in the clear is the window that matters.

Clipboard

The clipboard clears itself

Copying a password schedules its own erasure thirty seconds later, on every platform. A new copy cancels and replaces the pending timer.

def copy_with_auto_clear(secret: str,
                         timeout: int = 30) -> bool:
TTY

Alternate screen buffer

The interface runs in the alternate buffer, so nothing it drew is in your scrollback after you quit. Nothing to page back through, nothing in a terminal log.

SMCUP on start / RMCUP on exit
Signals

Signals restore the terminal

SIGTERM, SIGINT and SIGHUP all run the same handler: put the terminal back, clear the clipboard, exit. A killed session does not leave a mess behind.

SIGTERM / SIGINT / SIGHUP
  -> restore tty, clear clipboard, exit

At rest

The vault on disk

What survives a reboot, and what it costs to read it.

Cipher

AES-128-CBC via Fernet

Every entry is encrypted with Fernet — AES-128 in CBC mode with an HMAC-SHA256 tag over the ciphertext. Tampering fails loudly instead of decrypting to garbage.

token = Fernet(key).encrypt(plaintext)
# 0x80 | 8B ts | 16B IV | ct | 32B HMAC
Entropy

Fresh salt, fresh IV

A 16-byte salt from the OS CSPRNG at setup, and a new 16-byte IV for every single message. Encrypting the same password twice never produces the same bytes.

salt = secrets.token_bytes(16)   # once, at setup
Storage

The master password is never written

Only a derived digest of it reaches the disk. There is no server to send it to and no file that holds it.

~/.password_manager/secrets/
  .passwords.enc    .master_hash.enc
  salt.bin          .master_user.enc

Limits

What this does not do, and where it should not be trusted. These stay on the page whatever else changes.

  • Key protection is software-only. The vault key is protected by your password and by the OS keyring. There is no TPM and no Secure Enclave, and machine-id scoping is obfuscation rather than a hardware boundary.

  • The biometric check is not cryptographic. It is an OS authentication gate in front of a keyring-stored key. A process already running as you can read that key without presenting a fingerprint.

  • nuke cannot defeat an SSD controller. One overwrite pass, fsync, unlink. Wear-levelling, copy-on-write filesystems and journaling can all leave the original blocks. For guaranteed destruction, use full-disk encryption and destroy the key.

  • The key is not zeroed in memory. It is held as immutable Python bytes inside a Fernet object and cannot be overwritten in place.

  • No independent third-party audit. 157 self-authored tests are not an audit. Nobody outside the project has reviewed the cryptography. Treat this as beta software.
