Case study

How this VPS runs

Nine methods, one host. The map: research programmes, source admission, a governed platform, and a gate that refuses on the way out.

Context

Nine chapters on this site describe nine methods. Not one of them shows the thing they are part of, and a reader asked to assemble it from nine documents will not assemble it at all. This page is the map.

The estate is one virtual server: roughly 11 GB of memory and a 193 GB root filesystem, 87% of it used. One person built it over five months of dated artifacts, using agent tooling for the mechanical work. There is no cost figure anywhere in it — no measured spend, no compute or storage accounting was ever kept — so the only honest statement about cost is the bounded one: one host, five months, one operator, no fleet, and every scheduled job on it enumerable in a single command.

And nothing here has been audited by a third party. Every number on this site was measured on the host it describes, by the person who built it. The defence against that is not a credential. It is that each figure carries the command that produced it, and that the figures which came out badly sit in the same table as the ones that did not.

What I built

Read the map left to right. A programme is written before a build: vision, objective matrix, source census, gates. Sources are admitted one at a time, each becoming a collector with its own schema contract and crash-resume. Collection runs on a clock — 54 scheduled jobs, 43 timer units and 11 cron lines. What lands is governed: 397,679,393 rows across 28 named surfaces, one writer per database, a nightly contract that names the holes by name. Watchdogs reconcile the collectors from outside. A security office spans the whole width. Work is done by an agent organisation with declared write scopes. Everything published leaves through one gate.

Order of construction: the security office opened in March, the session changelog in April; the dead-man's switch armed and the gate ledger opened in June; the platform blueprint, the identity-hygiene law and the live transcript feed all landed in July; August was audits.

What I would do differently: four defects, all mine, all the same shape. A join keyword hid 55.8% of a corpus. A date fallback joined 179 calls to the wrong quarter. A filing family was sealed against every future run. An unbounded dependency shipped a package that could not start. None of them raised an error.

The nine chapters: research and discovery; source admission; platform architecture; automation and reliability; security and governance; agent operations; products and tooling; outputs and the honesty loop; transcript intelligence.

System map — layers left to right, the gate on the exit, the verify lane severed

Decisions

  • Chose one host with declarative scheduled units over a distributed stack with an orchestrator, because the failure I actually fight is absence of data mistaken for knowledge, and a surface I can enumerate in a single command makes absence loud where a fleet would bury it.

  • Chose a refusal at write time over a review step after publication, because a coverage contract that raises at the call site cannot be argued with — and a contract older than 36 hours counts as no contract at all, with no override parameter to reach for.

  • Chose an independent verification stage that re-runs the previous stages' commands from a fresh context over a self-report from the stage that did the work, because a gate that only ever passes is decoration — this one returned FAIL on the first case study, with six numeric mismatches.

Limitations

  • Nothing here has been audited by a third party. Every figure was measured on the host it describes, by the person who built it; the command is the only warrant offered.

  • There is no cost figure. No spend, compute or storage accounting was ever recorded, so cost can only be stated as a bound — one host, one operator, five months — never as a number.

  • The four-seat data office is designed governance, not a running system: the shared state store its charters require is absent from the host, so the task-closing path those seats declare as mandatory does not resolve. Read the separation of powers as a design.

  • Figures measured on one date do not generalise to another. The integrity run covered 40 of 40 databases in scope on 2026-08-09; the estate holds 54 today, and the difference is not a claim about the other 14.

  • This is not a claim that the pipeline has never missed a night, and not a claim of adoption for anything shipped. What the record supports is that the dead-man's switch has written no missed-run alert since it was armed on 2026-06-05.
